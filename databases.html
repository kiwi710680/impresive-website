Expanding Our Network

Bridging Diverse Data Environments Through a Common Interface

IMPRESIVE connects national claims, hospital electronic health records, and other approved data settings. While variations across these environments significantly strengthen the generalizability of findings, they also introduce analytical complexity. Here is how we onboard new data partners and evaluate new research questions.

Four readiness questions

What makes a database ready for a study?

Data readiness

Can the environment identify the target population, exposure, comparator, outcome, covariates, time zero, and follow-up?

  • Variable availability
  • Coverage and observation time
  • Fit-for-purpose CDM status

Method readiness

Can the common study design be implemented and checked consistently?

  • Protocol and code lists
  • Variable definitions
  • QA and analysis programs

Collaboration readiness

Can the local team and governance processes support distributed research?

  • Local PI and analysts
  • IRB and data-owner review
  • Output sharing and revision

Interpretation readiness

Can results be understood in their population and healthcare context?

  • Coding and clinical practice
  • Coverage and comparability
  • Heterogeneity and transportability

The instrument behind the readiness check

Eight source-data domains, assessed before conversion begins

Our Source Data Survey evaluates each data dimension, categorizing items as:

  • Directly Available: Ready for immediate extraction and mapping.
  • Derivable: Obtainable through variable transformation or secondary logic.
  • Not Available: Absent from the local data environment.

This structured assessment captures both data availability and the analytical effort required for harmonization.

Temporal granularity is a separate question.

Two environments can both carry a diagnosis date and still be incompatible for a study, because one records exact dates and another records only the month. That distinction constrains exposure windows, outcome ascertainment, and analytic time windows, and it is assessed alongside the domains above.

Data readiness self-assessment

Rate your own database against each variable. Every variable comes with its definition, comments, and conversion guideline, so you can judge it against what the conversion actually needs.

This tool provides an exploratory readiness check for early planning. It does not replace study-specific feasibility protocols or formal data reviews.

Four answers for every variable

  • AvailableRecorded directly in your source data.
  • DerivableObtainable by transformation, calculation, or linkage — for example, an end date from a start date plus days supplied.
  • Not availableAbsent from your data environment.
  • Not yet knownStill to be confirmed with the data owner.

How each table is judged

Only essential variables decide a table’s status — the identifiers, linking keys, and core date and code fields a table cannot be built without. The first rule that applies wins.

  1. An essential variable is not available

    Not ready

  2. An essential variable is unanswered or not yet known

    Incomplete

  3. An essential variable is only derivable

    Ready with derivation

  4. Every essential variable is available

Study-level decision

Readiness is not a permanent badge

The same data environment may be ready for one question and unsuitable for another. The decision must be revisited whenever the protocol, data period, definitions, or local environment changes.

Minimum feasibility record

  • Question and intended use
  • Required populations, variables, and follow-up
  • Local source and transformation assumptions
  • Quality findings and unresolved limitations
  • Governance, disclosure, and execution constraints
  • Interpretation plan for expected differences
